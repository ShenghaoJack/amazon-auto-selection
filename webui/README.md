# Amazon 选品流水线 · Web 运行控制台

纯 Python 标准库实现的本地控制台: 通过一页 HTML(`webui/index.html`)驱动流水线
(`python main.py ...`)的运行/中断/断点续跑/单步执行/重置, 并实时展示步骤状态、
运行输出、告警与体检报告。

## 启动

```bat
start_webui.bat            # Windows 双击即可
```

或手动:

```bash
python -X utf8 webui/server.py            # 默认 http://127.0.0.1:8790
python webui/server.py --port 9000        # 自定义端口
python webui/server.py --no-open          # 不自动打开浏览器
```

服务只监听本机 127.0.0.1。启动后自动打开浏览器访问 `http://127.0.0.1:8790`。

## 多类目并行(2026-09-15)

**同一个看板可以同时跑多个类目**(旧版是"同一时间只允许一个流水线子进程", 启动第二个会被
`已有流水线正在运行中` 拒掉)。

- **怎么用**: 在 🏠 类目中心对类目 A 点「续跑」/「打开运行台」启动后, 直接对类目 B 再点一次
  「续跑」即可 —— 两者会**同时运行**。切到哪个类目, ②步骤看板/③实时日志/运行横幅就显示
  **哪个类目自己的**内容(每个类目一份独立日志缓冲, 不会串台); 运行横幅右侧会显示
  `⧉ 并行中: <其它类目>`。
- **停止是"按类目"的**: ③ 运行台的「中断」只停当前查看的类目, 其它类目继续跑
  (`POST /api/stop` 带 `config_file`)。同一个类目仍然只允许一条流水线(重复启动会明确报错),
  因为双跑会互写 `step-status.txt`/产物。
- **共享资源怎么处理**(这是能不能并行的关键):
  | 资源 | 处理方式 |
  |---|---|
  | 亚马逊浏览器 Profile | **按类目隔离**(`data/profiles/amz-profile-<CAT>`, 首次使用从共享种子克隆登录态), 见 `core/profile_isolate.py` |
  | 卖家精灵浏览器 / CDP Chrome / 导出配额 | **按浏览器资源互斥**(`core/ss_lock.py`): 一个端口 = 一个 Chrome = 一份登录态。**不同类目配不同 `SS_CDP_URL` 端口(各自账号)= 不同的锁 → 真并行, 完全不等待**; 同端口的两个类目则**排队串行**(日志写明"在等谁", 上限 `SS_BROWSER_LOCK_WAIT` 默认 1800s)。**同端口 + 不同账号会被启动守门直接拦下**(一个 Chrome 只能保持一份登录态, 后跑的会用到前一个账号的配额与数据 —— 静默出错数据, 比排队危险), 并提示改用另一个端口 |
  | 卖家精灵 Profile | 同样按类目隔离(`ss-profile-<CAT>`); **自动拉起 Chrome 也用这个隔离目录**(`core/browser.py::effective_ss_profile`), 否则第二个账号的 Chrome 会因 user-data-dir 被占用而起不来 |
  | 亚马逊抓取(共用本机 IP) | **不做串行**(否则并行没意义): 步骤 0/1/10 并发抓取更容易触发亚马逊风控, 启动时会在日志里给出提示; 建议并行的类目**错开**启动, 或调大 `REQUEST_MIN/MAX_INTERVAL` |
  | 数据/日志/产物 | 本来就是按类目隔离(`data/<CAT>/…`), 互不影响 |
- **数据会不会互相污染(实测)**: 不会。并行跑两个类目(各 20 步 dry-run 全流程)后审计"窗口内被写入的所有文件": A 的 41 个产物全在 `data/A/`、B 的 41 个全在 `data/B/`、浏览器数据在 `data/profiles/amz-profile-<CAT>/`、归档在 `data/archive/<CAT>-<时间戳>/`(目录名带 CAT), **两类目目录之外没有任何非预期文件**。原因: 所有产物路径都由 `data/<CAT>/` 派生, 截图/下载/日志/告警/归档按类目分目录, 浏览器 profile 按类目隔离, 临时文件用 `tempfile.mkstemp`(全局唯一)。
  ⚠️ **但有一个真坑, 已修**: 看板给每次运行生成临时配置时, 文件名原来是 `run-<时间戳秒>-<配置名>.yaml` —— 而真实类目配置都叫 `config.yaml`, `.webui/runs` 又是全局共享目录, 于是**同一秒内启动的两个类目会算出同一个路径**, 后者覆盖前者; 若先启动的子进程还没读到配置, 它会加载**另一个类目**的配置 → 产物写进对方目录(**实测复现**) —— 这正是"数据互相污染"唯一的真实入口。现在文件名带 CAT 与随机后缀, 且清理旧快照时**跳过在跑运行的那份**(`prune_run_snapshots(protect=…)`)。
  **串数据审计清单(2026-09-15, 逐项静态扫 + 并行实跑核对)**: ①所有产物路径都由 `data/<CAT>/` 派生(平铺文件带 `<CAT>-` 前缀、独立目录按步骤名)、截图/下载/日志/告警/归档都在类目内; ②浏览器 profile 按类目隔离; ③临时文件 `tempfile.mkstemp` 全局唯一, 步骤13/14 的中间目录也建在类目内; ④`sellersprite` 已按端口/账号隔离; ⑤MCP/LLM 请求无本地状态。**排查出并修掉的 2 处真串数据入口**: (a) 看板临时配置同名覆盖(见上一段); (b) **归档目录前缀误配** —— `Paths.latest_snapshot()` 原用 `name.startswith(cat + "-")`, 类目名互为前缀时会串: 实测 `CAT=Cutting-Boards` 会把 `Cutting-Boards-US-202608-20260915-120000` 当成自己的最新归档(而 `data/<基类目>-<站点>-<月份>` 正是本项目常见命名), 后果是本轮产物被归档/同步进**另一个类目**的归档目录; 现改为精确匹配 `<CAT>-<YYYYMMDD-HHMMSS>[-N]`, 并用两个互为前缀的类目并行实跑验证: 各自归档 25 个自己的产物, 零混入。
  **按设计共享(不串数据, 但需知道)**: `data/.locks/`(锁 + 各浏览器资源的使用者记录)、`.webui/runs/`(各类目的临时运行配置; 类目中心的"历史快照"会列出全部, 已按内容 CAT 标注)、`.webui/config-backups/prune.log`(共享清理日志, 行内含 CAT)、`data/profiles/` 里的共享种子 profile(只作克隆源)、LLM/接口配额、本机 IP。
  **真正会互相影响的是"速率"而不是数据**: 两个类目同时抓亚马逊会共用本机 IP(更易触发风控 → 更多 `bot_blocked`/重试/转浏览器兜底, 失败行如实记 `ok=false` 且下次续跑重试), 以及共用 LLM 接口配额(可能 429, 会重试)。建议: 并行的类目**错开启动**, 或调大 `REQUEST_MIN/MAX_INTERVAL`; 卖家精灵则按端口/账号天然隔离。
- **注意**: 改的是 `webui/server.py` → **必须重启看板**(Ctrl+C 后重新 `start_webui.bat`)才生效;
  前端会按 `WEBUI_VERSION` 提示"旧构建"。命令行多开/批处理场景见 `scripts/parallel_cats.py`。
- **验证记录(2026-09-15)**: 同一看板同时启动两个类目(pid 17904 / 26196) → 各自
  `cat_running=true`、`run.cat` 各自正确、`other_runs` 互指、控制台 135/120 行互不串台;
  运行中重复启动同类目被拒(`类目「X」已有流水线在本服务运行中`); 只中断 A 后 B 仍在跑;
  `bootstrap.runs` 同时列出两条。另用 `scripts/parallel_cats.py` 双进程 dry-run 全流程
  同时跑通(67s / 66s, 各自独立 Profile), 并用两个真实进程验证了全局锁的跨进程互斥
  (后来者等待 5.4s 后拿到锁, 锁内记录正确)。

## 页面功能

> **两个视图(2026-09)**: 顶部导航切换「🏠 类目中心」与「▶ 运行台」。**刷新后恢复上次所在视图(2026-09-09)**: 浏览器记忆最近一次视图(`localStorage wui_view`), 刷新/重开不再无条件回类目中心——上次在「运行台」且选中的是真实类目(`data/…`) → 刷新后仍停在运行台; 上次在类目中心 / 或当前是占位模板 `config.yaml`(your-category-US-YYYYMM, 仅作 CLI/新建种子) → 回类目中心。首次使用无记忆默认类目中心。占位模板不进入配置列表/运行台(运行前会拦截占位 CAT)。

- **MCP 报 `SSL: UNEXPECTED_EOF_WHILE_READING`(2026-09-15 已缓解)**: 卖家精灵 MCP 端点解析出 16 个 A 记录(CDN 池), 部分节点会在 TLS 握手阶段 EOF —— 实测**全新连接 5% 失败**, 而**复用连接 0 失败且快 8.6 倍**。`core/mcp.py` 现已①复用同一个 `httpx.Client`(连接池/长连接) ②有会话时不再重复 `initialize` ③连接类错误自动重置连接与会话后重试。所以日志里偶见 `[MCP] … 第 1/3 次失败 … 2s 后重试` 属正常自愈; 若成片出现, 多为本机到该端点的链路问题(非密钥/额度), 可换网络复核。

## 说明与注意

- **「模式」选择只作用于本次运行(2026-09-15)**: 运行台的 dry-run / 真实 是**本轮临时覆盖**(`overrides`), 运行结束**不会写回** `data/<CAT>/config.yaml`(历史版本会写回, 曾把真实类目静默置成 `DRY_RUN: true` —— 配置中心就会给它打上 `DRY` 标)。要持久改模式请在⑤配置中心改并保存。
- **`LIST_URLS` 可以粘贴带语言前缀的地址(2026-09-15)**: 非美国站从地址栏复制常带语言偏好(如 `https://www.amazon.fr/-/en/gp/bestsellers/kitchen/3155139031`), 系统会**自动去掉该前缀**按规范短链接处理, 并在流水线日志写明 `LIST_URLS 已归一(去掉语言前缀): 原 -> 新`; 但**不要**填 `/Best-Sellers-…/zgbs/…` 旧版长链接(会被拒并提示改法)。
- **抓取类只剩一个开关 `FALLBACK`(2026-09-16; 2026-09-29 追加"有头兜底")**: ⑤配置中心有**独立分组「兜底(浏览器补抓)」**, 里面就一个下拉 **`FALLBACK`**(`auto` 默认 = 直连抓不到就自动用本机浏览器补回来; `off` = 完全不用浏览器)。其余细节全部内化、**表单不展示**(`FETCH_STALL_ROUNDS`/`FETCH_ASIN_TRIES`/`REQUEST_RETRY`/`BROWSER_FALLBACK_ROUNDS`/`BROWSER_ROUND_PAUSE`/**`BROWSER_HEADED_ROUNDS`** 等; 写了仍以配置为准)。⚠️ **步骤10 现在会自动用到"可见窗口"**: 无头补抓轮用尽后仍有未解决 ASIN 时, 程序会再开一个**有头浏览器窗口**补最后一轮(`BROWSER_HEADED_ROUNDS` 默认 1, 写 `0` 关闭) —— 因为无头 Chrome 更容易被亚马逊识别(同日实测: 桌面 Chrome 正常、裸 HTTP/无头吃验证码页)。**那个窗口由程序自己开关, 期间请勿手动关闭**。步骤01 详情与步骤10 变体共用这一个开关; 原先散在"抓取与复核调优"里的 `FETCH_ROUND_PAUSE` / `FETCH_STALL_ROUNDS` / `FETCH_ASIN_TRIES` 与从未登记、一直掉在**"其他参数(未登记说明的键)"**那坨里的 `BROWSER_FALLBACK_ROUNDS` / `BROWSER_ROUND_PAUSE` / `STEP01_BROWSER_FALLBACK` / `REQUEST_RETRY` **全部隐藏**(取值已内化到代码; 已加入 `HIDDEN_KEYS`, 所以从旧备份恢复配置也不会冒回表单)。**防风控维度**(`FETCH_WORKERS` / `REQUEST_MIN/MAX_INTERVAL` / `FETCH_LONG_*`)**保持不变、仍可编辑**。`index.html` 每次请求现读 → **刷新页面即生效, 无需重启看板**。
- **步骤1 取页策略可配**: ⑤配置中心可见并编辑 `STEP01_BROWSER_FALLBACK`(`auto` 默认 = 先按配置 COOKIE 走 HTTP 直连, 失败(风控/连接/解析)的 ASIN 自动转**真实浏览器**补抓, 用浏览器 Profile 的登录态; `always` = 全走浏览器; `off` = 只用直连)。**2026-09-16 起**: 该键已从界面隐藏(内化), 通用开关改用 `FALLBACK`; `STEP01_BROWSER_FALLBACK` 仍兼容且优先级更高(写在配置里照样生效, 只有 `always` 这种更细的取值需要它)。
- **接口错误语义(2026-09-15)**: 参数类错误 → **400**(消息可直接展示, 原为 500 + `ValueError: …`); **用户可见拒绝**(同类目重复启动 / 卖家精灵端口+账号冲突 / 维护命令撞车) → **409** + 原文提示(原为 500 + `RuntimeError: …`); 其余异常 → 500 + `类型: 消息`。
- **站点三口径要一致(2026-09-15 梳理)**: ⑤配置中心里的 `CAT` 后缀 / `SITE`(卖家精灵站点名) / `MARKET`(亚马逊域名)**要指同一个站**(如 `…-UK-202608` + `英国` + `amazon.co.uk`); 若 `SITE` 写成认不出的名字(`德国站`/`德`/`Germany` 之类), 系统会**告警并按美国站取数**(挖词/趋势就会拿到美国数据), 请改成官方站点名(`德国`)或域名(`amazon.de`); 换站后步骤0/1/8/10 走 `MARKET`, 步骤5/6 走 `SITE` → `marketplace`。

- **配置与备份管理(2026-09 类目配置模型)**: ①**每类目一份配置** `data/<CAT>/config.yaml`(该类目唯一当前配置), 配置下拉除根目录 `*.yaml` 外同时列出 `data/*/config.yaml`, **以类目名显示**(模板标注"占位模板(勿运行)"); 每轮运行会把生效配置**实时同步**到该类目文件, 归档快照把 config.yaml 一并纳入(`data/archive/<CAT>-<时间戳>/config.yaml`); ②配置保存自动备份(**随类目放**): 类目配置备份 = `data/<类目>/config-backups/<类目>-v<版本号>.bak`(旧集中 `.webui/config-backups/` 仅兼容/兜底), 头部带说明行(源文件/CAT/版本/原因/时间), **内容无实际改动则不生成备份**(仍为原数据; 保存确认「已保存 N 项」= 实际修改的字段数, 未改动键不计), 每类目只保留最近 10 份(`WEBUI_KEEP_CONFIG_BACKUPS` 可调)保存后自动清理; **每次备份事件(生成/跳过/失败)都会在控制台日志输出 `[备份事件] …`**; ③查看/治理备份: `python scripts/config_backup_tool.py list|restore|prune`(**2026-09-13 修复**: `prune --keep N` 原只用于打印、未传给 `prune()` → 实际按默认 10 生效, 现已真正生效; `restore <备份名>` 原只在 `.webui/config-backups/` 里找 → 备份主位置已是 `data/<CAT>/config-backups/`, 现按文件名在**全部备份目录**中查找; `list` 新增**版本缺号巡检**); 清理留痕: 自动/手动清理都追加到 `.webui/config-backups/prune.log` 与对应类目的 `17_备份与监控/pipeline-progress.log`(`[备份清理] 已删除 …`); 配置体检: `python scripts/check_configs.py`(只读核对格式与参数数量一致性); 类目历史存档里的 config 可用 `python scripts/config_backup_tool.py archive list|show|edit|delete|use` 读取/改动/删除/沿用; **开下月类目 = 手动**(推荐): 新建 `data/<类目>-US-<下月>/config.yaml`(复制上月文件), 在⑤配置中心手工改 CAT/月份(必要时 LIST_URLS)后保存并运行; `scripts/new_month_config.py` 仅作可选脚本化工具, 非推荐流程。**新建类目(新)** = ⑤配置中心右上「**＋ 新建类目**」向导: 填类目名(建议 `xxx-US-YYYYMM`, 月份自动填三个 MONTH)+ 复制自(推荐选一个真实类目继承 LLM/账号)+ 榜单 URL(可后补)→ 创建即自动生成 `data/<类目>/config.yaml` 并选中(服务端 `POST /api/category/create`; 需重启 webui 生效)。⚠️ **复制源的默认值(2026-09-14 核实)**: 下拉 = 全部配置(真实类目 `data/*/config.yaml` 排前, 根/模板排后), 顺序按**目录名升序**, 且前端不设 `selected` → **默认选中"字母序第一项", 不是"最近改动的那个"**, 也不跟随运行台当前选中的类目(改进项待定); 复制时服务端只改写 `CAT`/`LIST_URLS`(不填则清空)/三个月份, 其余键(含密钥/账号/阈值)原样继承; 源无法解析时回落到根占位模板(只会得到近乎空的配置)。

- 运行子进程使用启动本服务的同一个 Python 解释器(`sys.executable`), 以
  `-u -X utf8` 启动以保证输出实时、编码一致。
- **DRY_RUN 处理**: 项目 `main.py` 的 `run/step` 会把 `--dry-run` 的缺省值
  (False)当作参数强制覆盖配置文件里的 `DRY_RUN: true`, 因此本服务在有效配置
  判定为离线(dry-run)时会**自动附加 `--dry-run`**, 保证页面上的"继承配置/
  离线"模式与配置文件一致(离线绝不弹浏览器、绝不产生真实抓取/费用)。
- **真实模式**运行会弹出浏览器、访问 Amazon / 卖家精灵并产生真实抓取与 LLM 费用;
  页面会在非 dry-run 启动前二次确认。离线审查请选 `config.smoke.yaml` 或打开 dry-run。
- 运行期间的临时有效配置(基础配置 + 本次覆盖)写入项目根 `.webui/runs/`,
  进程结束后自动删除。
- 每次只允许一个流水线子进程; 中断后步骤状态停留在 RUNNING, 下次"全流程运行"
  会从该步自动重跑(与命令行断点续跑语义一致)。
